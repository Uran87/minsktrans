# МинскТранс — транспорт онлайн

SPA-карта городского пассажирского транспорта Минска в реальном времени.
Vanilla JS + Vite + OpenLayers, базовый слой — Google Tiles, данные — REST API СНОиПД.
Плюс собственный backend на Node.js + SQLite: хранит остановки, маршруты, расписания
и постепенно уточняет геометрию маршрутов по GPS-трекам. Внешний routing-движок
(OSRM/Valhalla) не используется.

## Что умеет

- Выбор типа транспорта (`bus`, `trolleybus`, `tram`) и номера маршрута из выпадающего списка backend.
- До выбора маршрута поле показывает placeholder «Выберите маршрут», а блок «Машины на маршруте» скрыт.
- Список маршрутов фильтруется с первого введённого символа; без ввода показываются все маршруты в порядке номеров.
- Выбор маршрута из списка сразу строит линию и загружает машины — отдельная кнопка «Показать маршрут» больше не нужна.
- На карте отображаются **все ТС выбранного типа** со всех маршрутов, а не только выбранный маршрут.
- **Сохранённая геометрия маршрута**: если backend уже накопил линию, карта рисует её вместо
  прямой «остановка → остановка». Пока линии нет — используется резервная прямая.
- Backend хранит остановки, маршруты, направления, остановки маршрута, перевозчиков и версии геометрии.
- GPS-треки собираются фоново и раз в неделю уточняют линию; OSRM/Valhalla не нужны.
- Обновление координат каждые **30 секунд** через `setInterval` (без WebSocket/SSE); кнопки «Стоп» больше нет.
- Маркеры машин с поворотом по полю `vector`; обновление через `feature.setGeometry()` без пересоздания фич.
- Весь транспорт на карте показывается с zoom 14; ТС выбранного маршрута — уже с zoom 12.
- Список «Машины на маршруте»: тип транспорта и номер маршрута, направление и следующая остановка.
  Появляется только после выбора маршрута.
  Карта при этом показывает все ТС выбранного типа, а список — только выбранный маршрут.
- Клик по машине: модель, рейс, направление, госномер и список остановок рейса с временем отправления; маршрут и тип транспорта — в заголовке карточки.
- «Остановки рейса» — отдельная прокручиваемая область; при открытии карточки следующая остановка автоматически ставится по центру списка.
- Клик по остановке в «Остановках рейса» — переход к ней: карта приближается, открывается карточка остановки с табло.
- Все остановки города отображаются на карте; остановки выбранного маршрута — крупнее и акцентным цветом.
- Остановки кластеризуются: до zoom 12 — в радиусе ~1000 м, с zoom 13 до 16 — ~200 м. Кластерный значок на 2 px больше обычного. С zoom 17 показываются отдельные остановки с подписями.
- Клик по остановке: попап с названием (RU/BY/EN), ID, координатами и пометкой, если остановка входит в выбранный маршрут. Остановка центрируется в свободной части карты справа от левой панели, поэтому попап не скрывается за ней.
- **Табло остановки**: для каждой остановки показываются маршруты и по два ближайших прибытия на маршрут
  (первое и следующее ТС), расстояние до остановки и время обновления; есть кнопка ручного обновления.
  Видимая область рассчитана на 4 маршрута; если их больше — появляется прокрутка, если меньше — блок сжимается.
- В табло кликабельна левая часть строки (тип, номер маршрута и направление) — активируется этот маршрут
  и тип транспорта в панели, карта центрируется на выбранном ТС, открывается его карточка; отметки времени прибытия некликабельны.
- Подсветка следующей остановки и пройденных остановок.
- Слои карты: схема, спутник, гибрид (сейчас Google Tiles, без ссылки на Google в атрибуции; на проде — другой провайдер); переключатель и зум справа снизу.
- Обработка ошибок API: уведомление, карта и уже загруженные данные не ломаются.
- Спиннер/прогресс-бар на время запросов.
- Демо-режим на реальных ответах API (маршрут №1) — чтобы приложение можно было посмотреть без доступа к API.
  У автобусов, троллейбусов и трамваев в демо свой набор машин и свои позиции.
- Адаптивная вёрстка: на мобильных панель уезжает в шторку, карточка машины — в нижний лист.

## Быстрый запуск в Docker

```bash
docker compose up --build -d
```

Открыть: **http://localhost:8080**

`docker compose` поднимает два сервиса:

- `api` — Node.js backend, SQLite (`/data/minsktrans.db`), фоновые задачи;
- `web` — nginx со статикой SPA и проксированием `/api/*` на backend.

При первом запуске backend пытается загрузить остановки, маршруты и расписания из API.
Если API недоступен, база остаётся пустой, а SPA работает в демо-режиме.
Логи загрузки:

```bash
docker compose logs -f api
```

По умолчанию при первом запуске включён **демо-режим** (маршрут №1, данные из `src/mock.js`).
Чтобы работать с живым API, выключите переключатель **«Демо-данные»** в панели слева —
запросы сразу пойдут в API через backend. Либо соберите образ с `VITE_MOCK_DEFAULT=false`.

Остановить:

```bash
docker compose down
```

Если порт `8080` занят, задайте другой:

```bash
APP_PORT=8081 docker compose up --build -d
# PowerShell: $env:APP_PORT=8081; docker compose up --build -d
```

Скопируйте `.env.example` в `.env` и при необходимости измените:

| Переменная | По умолчанию | Назначение |

| `AUTO_BOOTSTRAP` | `true` | При пустой базе сразу загрузить справочники |
| `JOBS_ENABLED` | `true` | Включить фоновый сбор GPS и построение геометрии |

## Локальная разработка

```bash
npm install

# терминал 1 — backend + фоновые задачи
npm run server

# терминал 2 — фронтенд
npm run dev
```

Открыть: **http://localhost:5173**

Vite проксирует запросы `/api` на `VITE_DEV_API_TARGET` (по умолчанию `http://localhost:3000`),
а backend уже проксирует `/api/v1/*` во внешний API и отдаёт локальные маршруты/геометрию.
При первом запуске демо-режим включён (маршрут №1); чтобы перейти на реальный API,
выключите переключатель **«Демо-данные»** в панели слева.
Демо-режим также можно отключить через `VITE_MOCK_DEFAULT=false` в `.env`.

Ручные задачи backend:

```bash
npm run sync                                  # bootstrap: остановки, ТС, маршруты, расписания
npm run worker -- sync-stops                  # или любая задача из списка
npm run worker -- discover-routes
npm run worker -- sync-schedules
npm run worker -- collect-traces
npm run worker -- build-geometry-first-pass
npm run worker -- build-geometry-full
npm run status                                # счётчики и последние запуски
```

Сборка и предпросмотр продакшен-версии:

```bash
npm run build
npm run preview
```

## Почему API работает без CORS

Браузер обращается не напрямую к `194.158.195.62:41290`, а к своему origin:

- в dev: `/api/v1/...` → Vite proxy → backend `http://localhost:3000` → внешний API;
- в Docker: `/api/...` → nginx → backend `api:3000` → внешний API или SQLite.

Backend также кэширует live-ответы на несколько секунд, чтобы не дёргать внешний API
на каждый запрос браузера. CORS-политика внешнего API при этом не важна.

## API

### Внешний API СНОиПД

Базовый URL: `http://194.158.195.62:41290/api/v1/`

| Метод | Endpoint | Использование |
|---|---|---|
| GET | `/geoinfomar?transport={transport}&route={Numl}` | координаты машин, поллинг раз в 30 с и сбор GPS-треков |
| GET | `/stops` | справочник остановок, ночная синхронизация |
| GET | `/vehicleState?id={vehicleId}` | госномер, рейс, направление, порядок остановок |
| GET | `/schedule?transport={transport}&route={Numl}` | оба направления, остановки и даты действия |
| GET | `/scheduleDay?transport={transport}&route={Numl}` | расписание на день, fallback для направлений |
| GET | `/scoreboard?idStop={stopId}&txt=false` | табло остановки и обнаружение маршрутов |
| GET | `/vehicles`, `/vehicle?id=` | справочник ТС, модель, госномер, `parkName` |

Значения `transport`: `bus`, `trolleybus`, `tram`, `routetaxi`. В ответах `/scoreboard` тип маршрута приходит в `mType` **кириллицей**: `А`, `Т`, `#`.

Реальные примеры запросов и ответов: `docs/api-real-samples.md`.

Ответы поддерживаются как в обёртке `StatusResponse` (`{ status, data }`), так и «голым» массивом/объектом.
Все live-запросы проксируются backend без сохранения ситуационных данных (только короткий кэш в памяти).

## Геометрия маршрута без OSRM

1. Из расписания берётся порядок остановок для каждого направления.
2. Пока GPS-данных нет, строится **placeholder** — прямые между остановками.
3. `collect-traces` опрашивает `/geoinfomar` и складывает точки в `gps_samples` (14 дней).
   Чтобы не заваливать API и диск, сбор идёт «фокус-группами»: 8 маршрутов опрашиваются
   каждую минуту в течение 6 часов, затем фокус переключается на следующие. Такой трек
   достаточно плотный для первого полного проезда.
4. Трек проецируется на последовательность остановок с монотонным прогрессом.
5. Для каждого участка «остановка A → остановка B» точки раскладываются по бинам вдоль участка,
   поперёк берётся медиана. Выбросы отсекаются по MAD. Так получается осевая линия коридора.
6. **Первый полный проезд** заменяет placeholder на `provisional`.
7. Раз в неделю несколько проездов объединяются; при достаточном покрытии линия становится `stable`.
8. Линия сглаживается, упрощается (Douglas-Peucker) и проверяется: все остановки рядом,
   порядок сохранён, длина в разумных пределах.

Статусы: `placeholder` → `provisional` → `stable`. Старые версии хранятся в `geometry_versions`,
текущая выбирается через `route_variants.current_geometry_id`.

Ограничения метода: это не road matching. На сложных развязках и параллельных дорогах
линия может требовать проверки; при малом количестве треков участок остаётся прямым.

Особенности формата:

- `departures` из `scheduleDay` трактуется как минуты от полуночи (`"314"` → `05:14`), также поддерживаются `"05:14"`.
- `marshrutStops` может быть массивом ID или объектов — оба варианта нормализуются.
- `marNuml` (в задании — `marNum1`) читается с fallback-полями.
- В `/scoreboard` поле `attributeFirst`/`attributeNext` — значение для табло (`A` — «сейчас», число — минуты,
  `-` — нет данных); если оно пустое, время считается из `estimatedTimeArrivalSecFirst/Next`.

## Замечания по реализации

- **Поллинг**: `setInterval(30_000)` запрашивает `/api/live/vehicles` — все ТС выбранного типа
  со всех маршрутов. Защита от наложения запросов (`inFlight`), пауза при скрытой вкладке. Кнопки «Стоп» нет.
- **Видимость ТС**: весь транспорт показывается с zoom 14; если выбран маршрут, его машины видны уже с zoom 12.
- **Производительность**: фичи машин живут в `Map<vehicleId, entry>`; при обновлении меняются
  `setGeometry()` и `setRotation()` иконки. Новые фичи создаются только для новых `vehicleId`,
  исчезнувшие — удаляются.
- **Поворот**: `rotation: (vector * Math.PI) / 180`, иконка-стрелка нарисована «на север».
- **Клик по машине**: `map.on('singleclick')` + `map.forEachFeatureAtPixel(..., layerFilter)`;
  остановки и линия маршрута кликам не мешают.
- **Клик по остановке**: карта центрирует её в видимой области справа от сайдбара,
  поэтому попап не уходит под левую панель.
- **Кластеры остановок**: до zoom 12 остановки объединяются в радиусе ~1000 м, с zoom 13 до 16 — ~200 м.
  Клик по кластеру приближает карту до zoom 13 (для дальних) или до zoom 17, где показываются отдельные остановки и подписи.
- **Следующая остановка в списке** вычисляется без дополнительных запросов: находится ближайшая
  остановка маршрута, затем из двух соседних выбирается та, что лучше совпадает с курсом `vector`.
- **Скролл остановок рейса**: список вынесен в отдельную рамку с собственной прокруткой; после рендера
  карточки `scrollTop` выставляется так, чтобы `.stop-item.is-next` оказалась в центре видимой области.
- **Ошибки**: при сбое запроса показывается тост; старые маркеры остаются на карте,
  следующий тик поллинга повторяет запрос.
- **Google Tiles**: `https://mt1.google.com/vt/lyrs=m|s|y&x={x}&y={y}&z={z}`,
  `crossOrigin` намеренно не задан (тайлы — обычные `<img>`, CORS им не нужен).
  Ссылка на Google в атрибуции убрана; для продакшена предусмотрена замена провайдера тайлов.
- **Демо-режим**: тот же код нормализации, что и для реального API; данные лежат в `src/mock.js`.
  В демо-режиме доступен маршрут №1 (автобус/троллейбус/трамвай — визуальный тип меняется).
- **Live-данные не сохраняются**: `/geoinfomar`, `/vehicleState`, `/scoreboard` проксируются
  backend с кэшем `LIVE_CACHE_MS` (8 секунд по умолчанию).
- **Все ТС на карте**: `/api/live/vehicles` агрегирует `/geoinfomar` по всем маршрутам выбранного
  типа в памяти backend и обновляет снимок каждые `LIVE_REFRESH_MS`. Браузер делает один запрос
  к backend вместо запроса на каждый маршрут.
- **Параметр `transport`**: наружу в API передаются `bus`, `trolleybus`, `tram` (и `routetaxi`).
  В `mType` табло используются коды `А`, `Т`, `#`; они переводятся во внутренние `bus/trolleybus/tram`.
- **Геометрия хранится версиями**: `geometry_versions` + `route_variants.current_geometry_id`.
  При первом полном проезде placeholder заменяется на `provisional`, после недельной агрегации — на `stable`.
- **SQLite**: файл в Docker-volume `/data/minsktrans.db`, режим WAL. Схема создаётся автоматически при старте.
- **Проверка геометрии без внешнего API**: `npm run seed:dev` создаёт синтетический маршрут,
  GPS-треки и прогоняет first-pass + weekly-aggregate.

## Если API доступен на другом порту

В задании упоминались адреса `194.158.195.62:41290` и `194.158.195.62:41291`.

API_ORIGIN=http://194.158.195.62:41291

и пересобрать/перезапустить контейнер:
