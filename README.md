# МинскТранс — транспорт онлайн

SPA-карта городского пассажирского транспорта Минска в реальном времени.
Vanilla JS + Vite + OpenLayers, базовый слой — Google Tiles, данные — REST API СНОиПД.
Проект полностью подготовлен к запуску в Docker.

## Что умеет

- Выбор типа транспорта (`bus`, `trolley`, `tram`) и номера маршрута.
- Кнопка **«Показать маршрут»**: строит линию по остановкам и запускает поллинг.
- Обновление координат каждые **30 секунд** через `setInterval` (без WebSocket/SSE).
- Маркеры машин с поворотом по полю `vector`; обновление через `feature.setGeometry()` без пересоздания фич.
- Список «Машины на маршруте»: тип транспорта и номер маршрута, направление и следующая остановка.
- Клик по машине: модель, рейс, направление, госномер и список остановок рейса с временем отправления; маршрут и тип транспорта — в заголовке карточки.
- «Остановки рейса» — отдельная прокручиваемая область; при открытии карточки следующая остановка автоматически ставится по центру списка.
- Клик по остановке в «Остановках рейса» — переход к ней: карта приближается, открывается карточка остановки с табло.
- Все остановки города отображаются на карте; остановки выбранного маршрута — крупнее и акцентным цветом.
- Клик по остановке: попап с названием (RU/BY/EN), ID, координатами и пометкой, если остановка входит в выбранный маршрут.
- **Табло остановки**: для каждой остановки показываются маршруты и по два ближайших прибытия на маршрут
  (первое и следующее ТС), расстояние до остановки и время обновления; есть кнопка ручного обновления.
- В табло кликабельны номер маршрута и обе отметки прибытия — открывается карточка соответствующего ТС.
- Подсветка следующей остановки и пройденных остановок.
- Слои карты: схема, спутник, гибрид (Google Tiles, с атрибуцией).
- Обработка ошибок API: уведомление, карта и уже загруженные данные не ломаются.
- Спиннер/прогресс-бар на время запросов.
- Демо-режим на реальных ответах API (маршрут №1) — чтобы приложение можно было посмотреть без доступа к API.
- Адаптивная вёрстка: на мобильных панель уезжает в шторку, карточка машины — в нижний лист.

## Быстрый запуск в Docker

```bash
docker compose up --build -d
```

Открыть: **http://localhost:8080**

По умолчанию при первом запуске включён **демо-режим** (маршрут №1, данные из `src/mock.js`).
Чтобы работать с живым API, выключите переключатель **«Демо-данные»** в панели слева —
запросы сразу пойдут в API через nginx-прокси. Либо соберите образ с `VITE_MOCK_DEFAULT=false`.

Остановить:

```bash
docker compose down
```

Если порт `8080` занят, задайте другой:

```bash
APP_PORT=8081 docker compose up --build -d
# PowerShell: $env:APP_PORT=8081; docker compose up --build -d
```

### Настройки (файл `.env`)

Скопируйте `.env.example` в `.env` и при необходимости измените:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `APP_PORT` | `8080` | Порт, на котором открывается приложение |
| `API_ORIGIN` | `http://194.158.195.62:41290` | Адрес API, доступный из контейнера nginx |
| `VITE_API_BASE` | `/api/v1` | Путь API, который использует фронтенд |
| `VITE_MOCK_DEFAULT` | `true` | Включить демо-режим при первом открытии |
| `VITE_DEV_API_TARGET` | `http://194.158.195.62:41290` | Куда Vite проксирует `/api` в dev-режиме |

## Локальная разработка

```bash
npm install
npm run dev
```

Открыть: **http://localhost:5173**

Vite проксирует запросы `/api` на `VITE_DEV_API_TARGET` — CORS не мешает.
При первом запуске демо-режим включён (маршрут №1); чтобы перейти на реальный API,
выключите переключатель **«Демо-данные»** в панели слева.
Демо-режим также можно отключить через `VITE_MOCK_DEFAULT=false` в `.env`.

Сборка и предпросмотр продакшен-версии:

```bash
npm run build
npm run preview
```

## Почему API работает без CORS

Браузер обращается не напрямую к `194.158.195.62:41290`, а к своему origin:

- в dev: `/api/v1/...` → Vite proxy → `http://194.158.195.62:41290/api/v1/...`;
- в Docker: `/api/v1/...` → nginx `proxy_pass` → `API_ORIGIN/api/...`.

Так один и тот же фронтенд работает и локально, и в контейнере, и не зависит от CORS-политики API.

## API

Базовый URL: `http://194.158.195.62:41290/api/v1/`

| Метод | Endpoint | Использование |
|---|---|---|
| GET | `/geoinfomar?transport={mType}&route={Numl}` | координаты машин, поллинг раз в 30 с |
| GET | `/stops` | справочник остановок (загружается один раз, кэш в памяти) |
| GET | `/vehicleState?id={vehicleId}` | госномер, рейс, направление, порядок остановок |
| GET | `/scheduleDay?transport={mType}&route={marNum1}` | расписание, фильтрация по `tripNum` и `direction` |
| GET | `/scoreboard?idStop={stopId}&txt=false` | табло остановки: маршруты и два ближайших прибытия |

Ответы поддерживаются как в обёртке `StatusResponse` (`{ status, data }`), так и «голым» массивом/объектом.
Если `status !== "success"`, выбрасывается `ApiError`, пользователь получает уведомление.

Особенности формата:

- `departures` из `scheduleDay` трактуется как минуты от полуночи (`"314"` → `05:14`), также поддерживаются `"05:14"`.
- `marshrutStops` может быть массивом ID или объектов — оба варианта нормализуются.
- `marNuml` (в задании — `marNum1`) читается с fallback-полями.
- В `/scoreboard` поле `attributeFirst`/`attributeNext` — значение для табло (`A` — «сейчас», число — минуты,
  `-` — нет данных); если оно пустое, время считается из `estimatedTimeArrivalSecFirst/Next`.

## Замечания по реализации

- **Поллинг**: `setInterval(30_000)`, защита от наложения запросов (`inFlight`), пауза при скрытой вкладке.
- **Производительность**: фичи машин живут в `Map<vehicleId, entry>`; при обновлении меняются
  `setGeometry()` и `setRotation()` иконки. Новые фичи создаются только для новых `vehicleId`,
  исчезнувшие — удаляются.
- **Поворот**: `rotation: (vector * Math.PI) / 180`, иконка-стрелка нарисована «на север».
- **Клик по машине**: `map.on('singleclick')` + `map.forEachFeatureAtPixel(..., layerFilter)`;
  остановки и линия маршрута кликам не мешают.
- **Следующая остановка в списке** вычисляется без дополнительных запросов: находится ближайшая
  остановка маршрута, затем из двух соседних выбирается та, что лучше совпадает с курсом `vector`.
- **Скролл остановок рейса**: список вынесен в отдельную рамку с собственной прокруткой; после рендера
  карточки `scrollTop` выставляется так, чтобы `.stop-item.is-next` оказалась в центре видимой области.
- **Ошибки**: при сбое запроса показывается тост, статус переходит в «Нет связи с API»,
  старые маркеры остаются на карте; следующий тик поллинга повторяет запрос.
- **Google Tiles**: `https://mt1.google.com/vt/lyrs=m|s|y&x={x}&y={y}&z={z}`,
  `crossOrigin` намеренно не задан (тайлы — обычные `<img>`, CORS им не нужен).
- **Демо-режим**: тот же код нормализации, что и для реального API; данные лежат в `src/mock.js`.
  В демо-режиме доступен маршрут №1 (автобус/троллейбус/трамвай — визуальный тип меняется).

## Если API доступен на другом порту

В задании упоминались адреса `194.158.195.62:41290` и `194.158.195.62:41291`.
Если рабочий API находится на `41291`, достаточно указать в `.env`:

```env
API_ORIGIN=http://194.158.195.62:41291
```

и пересобрать/перезапустить контейнер:

```bash
docker compose up --build -d
```
